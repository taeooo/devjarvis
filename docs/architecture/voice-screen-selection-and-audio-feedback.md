# Voice Screen Selection and Audio Feedback

## 문제 정의
- 수동 음성 입력으로 명령 텍스트는 인식되지만, `화면 번역 요청`처럼 화면이 필요한 명령에서 화면 공유 선택창이 뜨지 않는 문제가 있었습니다.
- 원인은 화면 공유 API가 사용자 직접 클릭 같은 transient user activation 안에서 호출되어야 하는데, 음성 녹음 → STT → 명령 라우팅이 비동기로 진행된 뒤에는 이 조건이 깨질 수 있기 때문입니다.
- 또한 음성 명령 후 DevJarvis가 음성으로 응답하지 않아 실제 음성 비서처럼 동작하지 않았습니다.

## 왜 이 작업이 필요한지
- 음성 명령은 텍스트 입력보다 피드백 지연과 실패 원인을 사용자가 파악하기 어렵습니다.
- 화면 공유 선택창이 뜨지 않는 경우 아무 일도 일어나지 않는 것처럼 보이므로, 명령 인식 후 다음 사용자 행동을 명확히 안내해야 합니다.
- 화면/OCR/프로젝트 분석 결과는 우측 결과 카드에도 남아야 하지만, 음성 명령에서는 짧은 음성 응답도 함께 필요합니다.

## 어떤 방향으로 해결했는지
- 음성 입력으로 들어온 명령은 `source=voice`를 유지하도록 변경했습니다.
- `화면 번역`, `화면 요약`, `화면 오류`, `이 화면 왜` 같은 화면 기반 음성 명령을 screen intent로 라우팅하도록 보강했습니다.
- 음성 명령이 화면 선택을 필요로 하면 즉시 화면 공유 API를 호출하지 않고, `화면 선택 필요` 결과 카드와 Voice 패널의 `화면 선택` 버튼을 표시합니다.
- 사용자가 `화면 선택` 버튼을 누르면 그 클릭 안에서 화면 공유 선택창을 열도록 하여 WebView 보안 조건을 만족시킵니다.
- Web Speech API 기반 음성 피드백을 추가했습니다.
  - `네, 말씀하세요.`
  - `화면을 선택해주세요.`
  - 처리 결과 요약
  - 실패 안내
- STT 전송은 JSON data URL 대신 multipart/form-data로 정리했습니다.

## 보안 경계
- 음성 원문은 Local Agent로만 전송합니다.
- 음성 원문은 NAS, Backend, AI Server로 보내지 않습니다.
- 화면 공유는 사용자가 명시적으로 버튼을 누른 뒤에만 실행됩니다.
- TTS는 브라우저/WebView의 로컬 SpeechSynthesis API를 사용합니다.
- 화면 이미지/OCR 원문/프로젝트 파일 원문 전송 경계는 변경하지 않았습니다.

## 현재 한계
- `헤이 자비스` wake word detector는 아직 실제 모델 감지가 아닙니다.
- 수동 음성 입력은 고정 시간 녹음 기반이며, 추후 무음 감지 기반 자동 종료가 필요합니다.
- 화면 명령 후 화면 선택창 자동 팝업은 WebView 보안 정책상 안정적으로 보장하기 어렵기 때문에 사용자 클릭 기반 CTA를 사용합니다.
