# Result History and User-Facing Context Cleanup

## 문제 정의
- 결과 패널에서 현재 결과만 눈에 띄고, 히스토리 목록은 충분히 보이지 않았습니다.
- 결과 카드 요약이 과도하게 잘려 사용자가 내용을 빠르게 파악하기 어려웠습니다.
- 우측 상태 패널에 `PROJECT Selected`, `RAG Project` 같은 개발 관점 상태가 노출되어 사용자 관점에서 중복되거나 불필요했습니다.
- 프로젝트 선택 상태는 상단 Project 카드에서 이미 확인 가능한데, 하단 상태 타일에서 다시 반복되어 UI 밀도가 높아졌습니다.

## 왜 이 작업이 필요한지
- DevJarvis는 개발자 도구 성격이 있더라도 최종적으로는 사용자가 빠르게 상태와 결과를 이해할 수 있어야 합니다.
- 히스토리 가시성이 낮으면 이전 진단 결과를 비교하거나 재확인하기 어렵습니다.
- 동일 정보를 여러 위치에서 반복하면 중요한 정보 밀도가 떨어지고 시선이 분산됩니다.

## 어떤 방향으로 해결했는지
- 결과 패널을 `현재`와 `히스토리`로 분리하고, 히스토리 영역은 독립 스크롤이 가능한 리스트로 변경했습니다.
- 히스토리 렌더 수를 늘리고, `히스토리 n건` 표기를 추가했습니다.
- 결과 카드 제목/요약의 line clamp를 완화해 잘림을 줄였습니다.
- 사용자 관점에서 중복되던 `Project`, `RAG` 상태 타일을 제거했습니다.
- 우측 상태 패널은 `Screen`, `Assistant`, `Voice`만 남겨 사용자에게 필요한 정보만 보이도록 단순화했습니다.
- 프로젝트 선택 여부는 상단 Project 카드에서만 확인하도록 유지했습니다.

## 보안상 고려사항
- 이번 변경은 표시 레이아웃과 사용자 노출 정보를 정리하는 작업으로, 파일 읽기/분석 경계는 변경하지 않았습니다.
- 개발용 내부 식별자나 추가 경로 정보는 새로 노출하지 않았습니다.

## 현재 한계
- 결과 히스토리는 현재 메모리 상태 기반이며, 앱 재시작 시 유지되지 않습니다.
- 사용량이 많아지면 검색/필터 기능이 추가로 필요할 수 있습니다.

## 다음 확장 방향
- 히스토리 검색/필터/고정(pin) 기능
- 결과 비교(diff) 보기
- 중요 결과 즐겨찾기 또는 세션별 분류
