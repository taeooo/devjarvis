# DevJarvis Local OCR First Pipeline

## Issue

DevJarvis handles screen capture data. Screen images and OCR text may contain private information such as messenger content, email, tokens, file paths, server addresses, browser tabs, and internal error logs.

The previous OCR path used the NAS Backend and AI Server OCR API:

```text
Desktop
→ Backend /api/screen/ocr
→ AI Server /internal/ocr/extract
```

This was useful as a pipeline foundation, but it means the selected screen image can move from the user PC to NAS services. For maximum-security desktop behavior, screen capture data should remain on the user PC whenever possible.

## Direction

Move screen OCR to the Local Agent first path.

```text
Desktop
→ Local Agent /internal/local-ocr/extract
→ Local Agent OCR provider
→ Desktop
```

The Local Agent remains loopback-only and runs on the user PC. The Desktop sends the selected screen image only to `127.0.0.1`, not to the NAS.

## Runtime Boundary

```text
User PC
├─ DevJarvis Desktop
├─ DevJarvis Local Agent: 127.0.0.1:17997
└─ Ollama: 127.0.0.1:11434

NAS
├─ Backend
├─ AI Server
├─ PostgreSQL
└─ Infra
```

The NAS firewall policy remains unchanged. Only HTTPS 443 should be externally exposed. Local Agent and Ollama ports are not opened on NAS and are not exposed from the user PC.

## Local OCR API

```text
GET  /internal/local-ocr/health
POST /internal/local-ocr/extract
```

`/internal/local-ocr/extract` accepts only bounded screen image payloads generated by Desktop capture logic.

## Security Rules

- Local Agent accepts loopback requests only.
- Desktop calls Local Agent via `http://127.0.0.1:17997`.
- Screen image is not sent to NAS for OCR.
- Screen image is not saved to disk by Desktop.
- Screen image is not saved to disk by Local Agent.
- Image MIME type is validated.
- Base64 data URL format is validated.
- Decoded byte size is validated.
- JPEG / PNG / WebP magic bytes are validated.
- Image dimensions are bounded.
- Byte size declared by Desktop must match decoded bytes.
- SVG/GIF and other image types are rejected.
- Local OCR failure does not automatically fallback to remote OCR.

## Provider Policy

The Local Agent supports provider switching.

```env
DEVJARVIS_LOCAL_AGENT_OCR_PROVIDER=placeholder
# or
DEVJARVIS_LOCAL_AGENT_OCR_PROVIDER=rapidocr
```

`placeholder` is useful for pipeline wiring. `rapidocr` enables real local OCR when dependencies are installed.

## Current Flow

```text
Text or voice command
→ screen target policy
→ user-selected screen/window capture
→ Desktop bounded JPEG generation
→ Local Agent OCR extraction
→ Local Agent / Ollama screen analysis
→ Desktop result panel
```

## Future Direction

The final maximum-security path should keep both OCR and LLM analysis local:

```text
Desktop
→ Local Agent OCR
→ Local Agent redaction
→ Local Agent model router
→ Ollama
→ Desktop result
```

NAS services should be used for project metadata, user configuration, result history metadata, and optional synchronized workflows, not for raw screen images by default.
